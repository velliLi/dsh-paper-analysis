# 创新性评估口径（三条基线 + A/B/C/D 分级）

创新性不是主观印象，是**相对于三个参照系的可测量差异**。评估时必须逐条对照，并把对照过程写进 `40-innovation.md`。

---

## 三条基线

### ① 自报最近邻（论文自己认为最接近的工作）
- 读取：Introduction 的"unlike [X]"、Related Work 的对比段落、每个方法的"Why not simply use X"。
- 必做：把作者对比的那句话翻译成"差异清单"，逐项标注：
  - `能力差异`：X 做不到什么（这是真差异）
  - `成本差异`：X 能做但代价高（这是工程差异，新意弱一档）
  - `设计选择`：只是选了不同参数/结构，且论文没证明更优（新意最弱，需消融支撑）
- 警惕：作者可能只挑弱对手作"最近邻"。若 Related Work 里明显少了一个强对手，记入 `50-critique.md` 的 Reviewer 发现。

### ② 同期同类（同年或同一会议/期刊的其他工作）
- 检索（`web_search` 至少 3 条，把命中的标题/年份/结论记入 `sources.md`）：
  1. `<核心方法关键词> <年份>` / `<core mechanism> <year>`
  2. `<任务名> <指标名> state of the art <年份>`
  3. `survey <主题> <年份>`（用于确认技术母题与已有分类）
- 判据：
  - 若存在同期更强结果 → 创新点降一档，并在报告里点名（不要替作者遮掩）。
  - 若同期工作用了相同的核心思想 → 标注"撞车"，创新性从"方法新颖"改为"首次在某约束/规模下实现"。
- **注意**：文档论文的"同期"以投稿/发表年为准，预印本早半年也计入。

### ③ 经典技术母题（领域公认的既有做法）
把方法还原成母题，母题清单（IC/EDA 常见）：

| 表象做法 | 可能的母题 | 新意判定 |
|---|---|---|
| 把固定系数换成可学习/可配置系数 | 参数化模板 | C 级，除非证明搜索空间或收益有质变 |
| 用手工规则换成搜索/强化学习/贝叶斯优化 | 设计空间探索 | C 级，除非改了搜索空间定义或成本模型 |
| 多个模块级联/并联并加门控 | 结构搜索/门控混合专家 | C 级偏 B，取决于消融 |
| 近似计算 / 量化 / 剪枝 | 精度—开销折中 | C 级，除非给出新的误差界或新硬件映射 |
| 把某算法映射到新型器件/存内计算 | 器件—算法协同设计 | B 级，需实测或 post-layout 证据 |
| 提出新的计算原语（例：新的数制、新的基本算子） | — | A 级候选，需理论或实测双重支撑 |
| 统一多个分离步骤为一阶段 | 端到端化 | B 级，需证明联合优于此前的分离最优 |

- 若"表象做法"对应的母题是表中已列项，且论文没有改变母题的**问题框架或成本模型**，上限为 C 级。

## 分级定义与判据

| 等级 | 名称 | 判据（满足才可评） |
|---|---|---|
| **A** | 新范式 | 改变了问题框架或引入新计算原语；不能用已有方法的参数化/组合解释；后续工作大概率跟。**必须**有理论论证或跨条件实测支撑。 |
| **B** | 新方法 | 在既有框架内提出新结构/机制/训练策略；有消融实验证明"去掉就退化"；收益不能被算力/调参解释。 |
| **C** | 新组合 / 新应用 | 已知模块的新组合，或迁移到新任务/新工艺节点/新约束；组合有效性**有待论证**（论文给出了初步证据但无对照分解）。 |
| **D** | 增量 | 工程微调、超参搜索、规模效应、更强的基线实现；差异可被调参或算力解释。 |

### 降级触发器（命中即降一档，并在报告里写明）
1. 无消融实验，只有端到端结果。
2. 对比基线由作者复现且未说明调参力度。
3. 只在自建数据集/自定场景上验证，无公开基准。
4. 提升幅度在方差范围内（论文未给方差 → 视为不确定）。
5. 核心机制与同期工作高度重合。
6. 结论依赖未公开的私有资源（数据、工具、工艺）。

### 升级触发器（命中可提一档，需显式说明）
1. 跨条件/跨工艺/跨规模重复验证一致。
2. 给出理论保证（误差界、收敛性、面积/功耗下界）。
3. 对手是强基线且由第三方实现（官方代码）。
4. 已被后续独立工作引用并复现成功（用 `web_search` 查引用）。

## 创新点的写法规范

- 标题**名词化**：「可配置近似加法器树」而不是「提出了一种更好的加法器」。
- 一句话必须包含 **相对对象**：「相对 <X>，本文 <做了什么>，从而 <把什么代价换成了什么>」。
- 必须给 **可证伪表述**：写清"什么实验结果会让这条创新点降级"。写不出可证伪表述的，说明这条创新点还是印象，不是判断。
- 创新点数量控制在 **1–4 条**。超过 4 条通常是没做技术分解，把实现细节当成了创新点。

## 常见误判（自己写报告时对照检查）

| 误判 | 表现 | 纠正 |
|---|---|---|
| 把"更大规模/更多数据"当创新 | "我们的模型更大所以更好" | 归入 D 级，除非给了规模—收益的规律 |
| 把"复现并改进基线"当创新 | 新 SOTA 但机制未变 | 检查是否只是工程调优 |
| 把"首次在 X 上做 Y"当 A 级 | 迁移类工作 | 判据是"新框架"而非"新场景"，通常 C 级 |
| 忽略同期工作 | Related Work 停在两年前 | 必查同期，撞车必须写明 |
| 用作者的话代替自己的判断 | "作者称该模块至关重要" | 要求消融数据，否则标 `证据不足` |
