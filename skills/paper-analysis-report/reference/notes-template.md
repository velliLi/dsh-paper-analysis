# 摘录版模板（三节，不含任何评级）

> 用途：这是三份交付物里最轻的一份——**只写这篇论文本身**，不评价、不分级、不给建议。
> 读者是"想快速知道这篇论文讲了什么、能借什么思路"的人（同门、跨方向的合作者、未来的自己）。
>
> 硬约束（出稿校验会强制检查）：
> 1. **只有三节**：论文在做什么 / 创新点 / 该论文提供的思路；
> 2. **不出现任何评级与判断用语**——`A/B/C/D 级`、`评级`、`值得跟进`、`我的结论`、`我认为`、
>    `局限`、`风险`、`复现难度` 等一律禁止（出现即 FAIL）；
> 3. 不带标题、不带表格、不写入 `[推断]`/`[论文未给出]` 之类标记、不写参考文献列表；
> 4. 篇幅最小，正文 **≤2000 汉字**（通常 600–1200 字即可）；
> 5. 数字必须能在详细版里找到（出稿时会比对）。
>
> 排印由 `make_docx.py` 自动套用：中文宋体小四、英文 Times New Roman、1.5 倍行距、全文黑色。

## 一、论文在做什么

<两到三段，纯客观转述：
第一段：论文处理什么问题、约束是什么、为什么这件事值得做（不评价作者做得对不对）。
第二段：核心做法拆成一条链——输入 → 关键机制 → 输出，用 2–3 个构件名，不展开公式。
第三段（可选）：作者报告的关键数字，写成"在 <条件> 下，<指标> 从 <A> 到 <B>"。>

## 二、创新点

<按条目分段落，一段一条。每条只写两件事：**相对什么做法不同**、**不同在哪里**。
不要写"为什么算新""分级""证据强度""可证伪表述"——那是详细版的内容。
条目数控制在 2–4 条；用"第一，……。第二，……。"衔接，不要用表格。>

## 三、该论文提供的思路

<三到四段，每段一条可迁移的思路。写法：先一句话说清这条思路的通用形式，
再说它能迁移到什么场景（可以是别的电路类型、别的任务、别的评价口径）。
**只讲"可以借用什么"，不讲"值不值得做"、不排名、不建议。**>

<全文到此结束：不要加"结论""建议""局限""详见详细版"这类尾巴。>
