# 交付前自检清单

逐条真实执行（用 `grep` 在 `paper.txt` 里搜、用 `read` 回看产物）。任何一条不通过就回去修，**不要带着 `[待核实]` 交差**。

## A. 事实与引用
- [ ] 报告里出现的每一个数字，都能在 `20-claims.md` 或 `30-experiments.md` 里找到条目 ID 与原文位置。
- [ ] 每一处 `> "引文"` 都用 `grep` 在原文里搜过，确认逐字存在（允许省略号，但不允许改写）。
- [ ] 没有把中文翻译冒充成英文引文。
- [ ] 论文没给的信息，写的是 `[论文未给出]` 而不是猜的数。
- [ ] 所有我自己的判断都带 `[推断]`，并给出可验证方式。
- [ ] 只有一处来源支撑的结论标了「单点证据」。

## B. 实验口径（IC 专项）
- [ ] 每个功耗/能耗数字都带了：工艺节点、Vdd、频率、工艺角、是否含外设。
- [ ] 每个面积数字都说明是核心面积还是总面积，是否同工艺节点比较。
- [ ] 时序/速度结论注明了是否 post-layout。
- [ ] 「提速/省电 X 倍」写清了相对谁、在同什么条件下的百分比。
- [ ] 明确标注了证据等级（实测 / post-layout / RTL / 算法级 / 理论），且没有跨级外推。
- [ ] 跨工艺或跨电压的对比处标了「不可直接比较」。

## C. 创新点
- [ ] 做了技术分解（3–6 个构件），每个构件标了 已知 / 已知但改造 / 新提出。
- [ ] 三条基线都对照过：自报最近邻、同期同类（有检索记录与链接）、经典母题。
- [ ] 每条创新点都有可证伪表述（写清什么实验结果会让它降级）。
- [ ] 创新点在 1–4 条之间；没有把实现细节当创新点。
- [ ] 撞车/被超越的同期工作如实写进报告，没有替作者遮掩。
- [ ] `sources.md` 里记录了检索用的查询词与命中结果的链接与年份。

## D. 报告结构与一致性
- [ ] 摘要卡里的「最强结果」「创新点等级」「我的结论」与正文第 4、5、6 章一致。
- [ ] 第 6 章局限分成「作者承认的」与「我发现的」两类，且与 `50-critique.md` 的处置对应。
- [ ] 报告里明确写出「论文没有回答的问题」。
- [ ] 第 8 章的复现路线标出了卡点（数据/工具/算力/工艺），不是"照着做就行"。
- [ ] 不适用的章节已删除，没有留下空壳标题。

## E. 产物与可复用性
- [ ] 该篇文献有**自己的独立文件夹**（`PaperAnalysis/<日期>_<短标题>/`），里面 `reports/` + `analysis/` + `assets/` + `sources.md` 齐全，没有与别的论文混放。
- [ ] `reports/` 里只有六份报告文件（三版 md + 三版 docx），没有中间件、没有校验 json。
- [ ] 目录结构符合 `SKILL.md` §4：`reports/` + `analysis/00-context.md`…`60-method.md` + `analysis/source/paper.txt` + `assets/` + `sources.md`。
- [ ] 目录名日期为 `YYYY-MM-DD`，短标题为英文小写连字符；两版文件名只差"详细版/简略版"。
- [ ] **简略版为 2–3 页**（正文 2000–3200 汉字；页数以汉字数为准，`--pages` 不可靠）。
- [ ] **简略版是整段文字**：通常 0 张表（最多 1 张），数字与条件写在句子里，读起来像人写的报告。
- [ ] **两版都在且数字一致**：简略版每个数字都能在详细版里找到（含详细版 Mermaid/代码块里的值）。
- [ ] **出稿校验结论为 PASS**（工具输出"结果：全部通过"，或 `analysis/check.json` 里 `verdict: PASS`）。
- [ ] **摘录版只有三节**（论文在做什么 / 创新点 / 该论文提供的思路），且**通篇没有评级、判断与建议用语**。
- [ ] 简略版没有证据链标记（`[推断]`/`[论文未给出]`）、公式块、Mermaid 源码、参考文献列表。
- [ ] Mermaid 图在 markdown 里能渲染（预览过一次）；Word 版的图示已按 `docx-export.md` §4 处理。
- [ ] 中间件文件可被下一篇论文复用（没有把本篇特定内容写进模板部分）。
- [ ] 引用信息给了 BibTeX 或 GB/T 7714 至少一种。
