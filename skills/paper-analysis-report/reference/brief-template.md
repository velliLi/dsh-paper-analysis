# 简略版模板（2–3 页，整段文字，手打报告风格）

> 使用说明：这是**简略版**模板。目标是让导师/同学读 2–3 页连续文字就知道"这篇论文值不值得跟"。
> **写法就是手打报告的写法：整段叙述，不摆表格。** 表格是详细版的工具，简略版里最多留 1 张
> （只在某个数据关系实在非表不可时），通常应为 0 张。
> 本版**带判断**（值不值得跟、从哪切入、最大风险）。若只想要论文本身、不要评价，
> 用 `notes-template.md` 写摘录版。
> **不要写标题**（文件名即标题，封面与标题行都不生成）；**不要单列"一句话结论"**——
> 判断直接写进"论文在做什么"的第一段；**不要写"需要向作者确认的问题"**（那属于详细版）。
> 硬约束：不出现 `[推断]`/`[论文未给出]` 等证据链标记、公式块、Mermaid 图、复现参数、参考文献列表；
> 每个数字都必须能在详细版里找到（出稿时会自动比对）。
> 排印：中文宋体小四（12 pt）、英文 Times New Roman、1.5 倍行距，由 `docx_export.py` 自动套用。
> 篇幅：正文 2000–3200 汉字（对应 A4 两到三页）。

## 一、论文在做什么

<第一段就给出判断，别绕：创新点最高等级 + 最关键的一个数字（带条件）+ 值不值得跟。
第二段交代问题与已有做法的瓶颈（瓶颈要写具体代价，不要写"效果不佳"）。
第三段把方法讲成一条链：核心构件 → 关键机制 → 得到什么功能。用 2–3 个构件名，不展开公式。>

## 二、创新点

<按创新点分段写，一段一条。每条一段话里要包含四件事：相对谁新、为什么算新、有什么证据、
我的分级（A/B/C/D 级）。段首可用加粗短句点题，例如"**最强的一条是……**"。
按分级从高到低排；对证据不足的那条要直接说清它缺哪一组对照，以及缺了会降成什么级。>

## 三、实验做到了什么程度

<两段。第一段写器件/算法层实测数据（原始数字 + 条件：偏压、波长、封装、工艺角、样本量等），
并明确证据等级（实测 / post-layout / RTL / 算法级 / 理论）。第二段写系统层演示的性质，
并说清哪些数字是实测、哪些是拓扑计数或推算。>

## 四、主要问题

<三到五段，每段一个要害问题，按严重度排。写法：现象 → 具体数字或缺失项 → 会导致什么结论不成立。
最后一段尽量收束到一句"若结论为假，最先在哪一句上崩"。>

## 五、复现与建议

<三段。第一段：复现难度与小复现目标（先做哪一块，卡在哪个参数没给）。
第二段：我会怎么用它（引用时只引哪些结论、哪些不要引）。
第三段：值得投入的切入点 1–2 个，各配依据、预期收益与所需资源。>

<全文到此结束。**不要**在末尾加"详见详细版/过程档案见某目录"这类指引句——
交出去的就是这一份自足的文字报告。>
