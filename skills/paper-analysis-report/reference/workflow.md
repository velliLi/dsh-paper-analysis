# 流水线执行手册（P0–P7）

本文是 `paper-analysis-report` 的**操作层**。SKILL.md 给判定标准，本文给逐步动作。
所有阶段产物都写文件，路径相对本次分析目录 `<OUT>/`。

---

## P0 立项（5 分钟）

**目的**：把"帮我看看这篇论文"变成一个有边界、可验收的任务。

动作：

1. 判定材料形态并确定取文本策略：

| 形态 | 取文本策略 | 降级路径 |
|---|---|---|
| 本地 PDF 路径 | 先试 `pdftotext -layout paper.pdf paper.txt`（poppler）；次选 `python -c "import pypdf"`；再次 `pwsh` 调用 Word/Edge 打印无意义，不推荐 | 若无任何提取工具：让用户提供正文文本，或按页截图后用 `read_image` 逐页读 |
| arXiv 链接 | `web_fetch` 抓 abs 页获得摘要与元数据；正文抓 `https://arxiv.org/abs/<id>` 不足以替代 PDF，优先请用户下载 PDF | 用 `web_fetch` 抓 HTML 版（`arxiv.org/html/<id>` 若存在） |
| 用户粘贴正文 | 直接落盘 `paper.txt`，记录来源 | — |
| 图片/截图 | `read_image` 逐张读，边读边记页码 | 需要更多页时明确向用户索要 |

2. 判定论文类型（决定后续重点）：**电路实现类**（芯片/数模混合/存储）、**EDA/算法类**（设计自动化、优化、学习型方法）、**器件/工艺类**、**系统与应用类**、**综述/展望类**。综述类不走 P3 的完整实验解剖，改走"文献计量 + 分类框架"。

3. 写 `00-context.md`：

```markdown
# 00 立项
- 材料：<路径或链接>（形态：PDF/HTML/图片/文本；页数）
- 论文：<标题> / <作者> / <发表处+年份> / DOI 或 arXiv ID
- 类型：<五类之一>；学科口径：集成电路工程-<子方向>
- 分析深度：<完整报告 / 仅实验 / 仅创新点 / 多篇对比>
- 已知背景：<用户提供的上下文，例如"这是我课题的 baseline">
- 待澄清问题：<最多 3 条；不要停下来等答案，先假设后标注 [假设]>
```

**Gate**：`00-context.md` 存在，且材料能被实际读取到（不是"应该能读"）。

## P1 通读建骨（先骨架，后血肉）

**目的**：在不被细节淹没的前提下，拿到论文的**逻辑骨架**，并暴露"哪些地方作者在含糊"。

一页一问的顺序（每问一句话答案，落 `10-outline.md`）：

1. **他们解决什么问题？** 用一句不含"高效""新颖"的句子复述。
2. **为什么以前解决不了？** 作者声称的 gap 是什么？这个 gap 是"能力不足"还是"成本太高"？
3. **他们的核心手段是什么？** 只用动词和名词，不用形容词。
4. **凭什么说它有效？** 作者列出的最强证据是哪一个图/表？
5. **边界在哪？** 作者自己承认的适用条件（工艺节点、模型规模、数据集分布）。
6. **哪里读不懂/自相矛盾？** 逐条记下页码——这些是 P5 的弹药，不是你的失败。

`10-outline.md` 结构建议：每节一个小标题（Introduction / Method / Results / ...），下面写"该节要回答的问题 → 作者的答案 → 我的疑问"。

**Gate**：能不看原文说出 5 分钟的口头摘要（写进 outline 顶部作为"电梯稿"）。

## P2 证据提取（主张—证据表）

**目的**：把"作者说了什么"和"证据能支撑什么"分开。

对所有 **claim（主张）** 建表，写入 `20-claims.md`：

```markdown
| ID | 主张（照抄原文关键句） | 原文位置 | 证据类型 | 证据强度 | 我的判定 |
| C1 | "we reduce energy by 41% over X" | §V-B, Table III | 实测/仿真/对比 | 强/中/弱 | 成立/有条件成立/证据不足 |
```

- **照抄原文**：英文原文保留，不改写、不翻译后当引文。翻译放在"我的判定"里。
- **证据类型**：实测芯片 / post-layout 仿真 / RTL 仿真 / 理想模型仿真 / 仅理论界 / 引文他人结果。
- **证据强度判据**：是否有基线对照？是否同工艺同条件？是否给方差或多次运行？是否公开代码/数据？
- **单点证据**：全篇只有一处支撑的主张，显式标注 `单点证据`。

**Gate**：每条 claim 都有可被机器搜索到的原文片段（后续会回查）。

## P3 实验解剖

**目的**：让"实验部分"变成可复现的操作说明，而不是结果复述。

`30-experiments.md` 必含 6 张表：

1. **数据集/测试用例表**：名称、规模、划分方式、是否公开、是否有隐藏测试集、是否自建（自建需注明构造方法）。
2. **基线表**：基线名、论文版本/年份、来源（原论文 or 作者复现）、是否重新调参、作者给出的对比条件。→ **关键判据：作者复现的基线是否"弱化"**（例：只跑默认参数、只在小规模上比）。
3. **指标表**：指标全称、定义式、单位、测量条件（见 `ic-domain-notes.md`）、论文报告的是均值还是最优值。
4. **主结果表**：按原文 Table/Figure 号逐个搬运**准确数字**，标注该数字来自哪张图表；对每组对照写一句"差异是否被作者解释"。
5. **消融/敏感性表**：去掉了什么、掉多少、是否单调、是否只做了单向消融（只做"去掉"，不做"换成等价模块"）。
6. **开销表**：时间/面积/内存/功耗/编译或综合时间；是否含训练成本；是否有 scalability（规模扩展）实验。

每张表下写 2–4 行 **"我的解读"**，必须区分：
- `作者主张` → `数据支持到什么程度` → `还缺什么对照才能坐实`。

**Gate**：任何一个被引用进报告的数字，都能在此文件里定位到"原文 Table/Fig + 数值"。

## P4 创新点鉴定

**目的**：产出**可被导师追问而不倒**的创新点陈述。

三步：

1. **技术分解**：把核心方法拆成 3–6 个构件（如 input embedding / 计算单元阵列 / 调度策略 / 训练目标 / 外设接口）。每个构件标注：`已知？/ 已知但改造 / 新提出`。写入 `40-innovation.md`。
2. **三条基线对照**（口径见 `novelty-rubric.md`）：
   - ① **自报最近邻**：论文自己说最接近的工作。逐条对比"差在哪、这个差是被证明有效还是只是设计选择"。
   - ② **同期同类**：用 `web_search` 检索同期（同年 ±1，或同会议）/同任务工作，判断是否"撞车"。至少检索 3 条查询：`<方法关键词> <年份>`、`<任务> <指标> state of the art <年份>`、`survey <主题> <年份>`。
   - ③ **经典母题**：这个方法是否只是某经典方法的参数化（例：把固定系数换成可学习系数、把手工调度换成强化学习）。
3. **分级 + 可证伪表述**：按 A/B/C/D 分级，每条创新点写成**可被实验否证**的一句话：

```markdown
### 创新点 1：<名词化标题>
- 构件：<对应技术分解哪一项>
- 相对基线差异：<与 ①/②/③ 的具体差异>
- 为什么算新：<不是"没人做过"，而是"此前做法做不到/代价高，因为...">
- 支撑证据：<消融表行号 / 主结果表列 / 引文>
- 分级：B 级（理由一句话）
- 可证伪表述：若 <对照实验> 显示 <预期反例>，则本创新点降为 C 级
- 复现所需信息：<论文是否给全？缺什么？>
```

**Gate**：每条创新点都有"可证伪表述"；没有一条创新点只靠"作者说是新的"支撑。

## P5 对抗验证（默认用 workflow 工具扇出）

**目的**：让报告在组会/审稿场景下不被一句话击穿。

三个独立审查角色（各自看不到彼此结论）：

| 角色 | 任务 | 必须回答 |
|---|---|---|
| **复现者 Reproducer** | 假设我要在 2 个月内复现 | 论文缺哪些参数/超参/工艺设置？哪一步不可复现？等价替代会破坏什么？ |
| **历史学家 Historian** | 定位技术谱系 | 这个方法的最早雏形是什么？同期是否有更强工作？有无被后续工作超越或证伪？ |
| **审稿人 Reviewer** | 找实验设计的漏洞 | 基线公平吗？消融够吗？统计显著性/方差？指标是否选择性报告？结论是否超范围外推？ |

要求每个角色输出结构化 JSON：

```json
{ "role": "reproducer",
  "findings": [ { "id": "R1", "severity": "high|medium|low",
                  "claim": "一句话指控", "evidence": "原文位置或缺失点",
                  "what_would_settle_it": "需要什么对照/数据" } ] }
```

主 Agent 在 `50-critique.md` 里逐条处理：**接受 / 反驳（附证据）/ 存疑**。
反驳必须引原文；不能反驳的写成报告的"局限与风险"（分"作者承认的"和"我发现的"两类）。

**Gate**：三个角色都跑过；每条 high 严重度发现都有明确处置；报告第 6 章与之对应。

## P6 重构与图示

**目的**：把方法讲成"如果我来实现，我会怎么搭"。

`60-method.md` 必含：

1. **Mermaid 数据流/结构图**：输入 → 各级处理 → 输出，标出每个模块名与关键维度/位宽/规模；控制路径用虚线，数据路径用实线。
2. **符号表**：公式中每个符号的名称、含义、量纲、取值范围。
3. **算法伪代码**（若适用）：训练与推理分开写；把论文没写清的步骤标 `[需假设]`。
4. **复现关键参数表**：超参、位宽、工艺节点、电源电压、频率、工具与版本、仿真/实测条件。
5. **实现难点清单**：作者一笔带过但对复现致命的地方（例："训练 10 天"、"需要私有数据"、"依赖特定 EDA 版本"）。

**Gate**：一个没读过原文的同学，靠这一份文件能画出系统框图。

## P7 报告写作（三版）

**目的**：先写详细版（结论与数字的唯一来源）→ 抽简略版（带判断）→ 再抽摘录版（去判断）。

详细版按 `report-template.md` 填空，组装顺序建议：

1. 先写第 3–6 章（方法/创新点/实验/局限）——它们是主干。
2. 再写第 2 章问题与动机（此时你对问题的理解最准确）。
3. 最后写摘要卡（第 1 章）与第 8 章"对我的研究"——摘要卡必须与正文一致。
4. 回查引文：对报告里每一处引号内的句子，在 `analysis/source/paper.txt` 里搜索确认存在；搜不到的删掉或标 `[待核实]`。

简略版按 `brief-template.md` 抽取，纪律：

- **写成整段文字，手打报告的样子**。六节：一句话结论 / 论文在做什么 / 创新点 / 实验做到了什么程度 /
  主要问题 / 复现与建议 / 需要向作者确认的问题（后两节可合并）。
- **只搬结论，不搬论证**。判据：这句话拿掉之后，读的人还能不能做决定？不能就别删。
- **不摆表格**（通常 0 张，非表不可时最多 1 张）；数字与条件写在句子里。
- 正文 2000–3200 汉字（约 2–3 页）。超了先砍"主要问题"里的次要条目，不要改字号。
- 不出现 `[推断]`/`[论文未给出]` 之类标记、公式块、Mermaid 源码、复现参数、参考文献列表。
- 简略版的每个数字都必须能在详细版里找到（出稿时会自动比对）。

摘录版按 `notes-template.md` 抽取，纪律最严：

- **只有三节**：论文在做什么 / 创新点 / 该论文提供的思路；
- **不评级、不判断、不建议**：不写 `A/B/C/D 级`、不写"值得跟进/不值得"、不写"我的结论/我认为"、
  不写"局限/风险/复现难度"——出现即校验 FAIL；
- 创新点只写"相对什么做法不同、不同在哪里"，不写"为什么算新"/"证据强度"/"可证伪表述"；
- 第三节只讲可迁移的思路，不给排名与建议；正文 ≤2000 汉字。

**Gate**：三版 markdown 都写进 `reports/`，文件名分别以「详细版 / 简略版 / 摘录版」结尾。

## P8 出稿与校验

**目的**：把 markdown 编译成 Word，并用机器检查兜住低级错误。

执行（本 preset 自带工具，细节见 `docx-export.md`）：

```
paper_docx(
  detailMd = "<OUT>/reports/<slug>_详细版.md",
  briefMd  = "<OUT>/reports/<slug>_简略版.md",
  notesMd  = "<OUT>/reports/<slug>_摘录版.md",
  outDir   = "<OUT>/reports",
  source   = "<OUT>/analysis/source/paper.txt"
)
```

它会生成三版 `.docx` 并检查：残留未解决标记、简略版与摘录版的必备章节与篇幅、
**摘录版是否混入评级/判断用语**、三版数字一致性、英文引文能否在源文本中逐字找到、图片引用是否存在。

处置规则：

- **简略版超 3 页** → 删内容而不是改字号：先砍"局限"的次要条目，再砍核心结果的行。
- **引文核对 FAIL** → 引文不是逐字照抄，或 `analysis/source/paper.txt` 不是原文；改引文或重新抽取正文。
- **两版数字不一致** → 以详细版为准改简略版（详细版是数字的唯一来源）。
- **`[待核实]` 残留** → 回 P2/P3 补证据，补不到就删掉该论断。

**Gate**：工具输出"结果：全部通过"（`analysis/check.json` 的 `verdict` 为 `PASS`），
且 `reports/` 目录里只有六份报告文件（三版 md + 三版 docx）。
