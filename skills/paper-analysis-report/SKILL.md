# 论文分析报告流水线

把一篇（或多篇）论文变成一份**可直接用于组会汇报、开题铺垫、复现计划**的分析报告。
报告的判定标准不是"读起来像摘要"，而是：**每一条结论都能指回论文中的证据；每一处推断都标明了推断等级。**

## 0. 三条铁律

1. **零编造**。论文没写的数字不写；不确定就写 `[论文未给出]`、`[推断]`、`[待核实]`。**绝不**为了表格好看而补一个"看起来合理"的值。"大概提升了 20%" 这种模糊表述一律改成原文的准确数字加引号。
2. **证据优先**。所有关键论断附 `原文节号/页码/图表号` 与一句原文引文（英文原文照抄，不改写）。在产出报告前必须回查每一处引文确实存在于原文。
3. **推断分级**。凡是你自己的判断（"这里可能是为了省面积"），必须显式标记 `[推断]`，并给出可证伪的验证方式（"若附录 A 给出该模块门数即可确认"）。

## 1. 开工前的三件事

- **确认材料形态**：本地 PDF / arXiv 链接 / 用户粘贴的正文 / 图片截图。见 `reference/workflow.md` §1 的取文本策略与降级路径。
- **确认分析深度**：默认产出【完整分析报告】。若用户只想要某个切片（例：只要实验部分），只跑对应阶段，但仍然保留证据与推断标记。
- **建目录**：在工作区建立本次分析的产物目录，路径规则见 §4。产物必须落盘成文件，不能只留在对话里。

## 1.5 可迁移运行（脱离本 preset 也能用）

本技能的出稿与校验**不依赖任何特定 Agent 预设**：三份 Word 与校验都由 `tools/` 里的脚本完成，
只要机器上有 Python 3.8+ 与 `python-docx` 即可。

```bash
python tools/check_env.py                     # 先体检：依赖 + 文件完整性
python tools/make_docx.py --auto \
  --input <详细版.md> <简略版.md> <摘录版.md> --out <reports>
python tools/check_docx.py \
  --md <详细版.md> <简略版.md> <摘录版.md> \
  --detail-docx <详细版.docx> --brief-docx <简略版.docx> --notes-docx <摘录版.docx> \
  --source <analysis/source/paper.txt>
```

三份 markdown 必须有文档头 `<!-- meta: {...} -->`，其中 `version_label` 取 `detail` / `brief` / `notes`
（`--auto` 靠它判断版本；也可用 `--kind` 显式指定）。

**手动跑（没有 Agent 时）**：按 `reference/workflow.md` 的 P0–P7 自己写三份 markdown，再跑上面两条命令即可。

**分发本技能**：整个 `paper-analysis-report/` 目录自成一体，拷给别人就能用
（详见技能目录里的 `README.md`）。若对方也用 DSH，放到 `<预设目录>/skills/` 或 `~/.dsh/skills/`。

## 2. 流水线（9 个阶段）

| 阶段 | 名称 | 产出文件 | 关键动作 |
|---|---|---|---|
| P0 | 立项 | `analysis/00-context.md` | 材料清单、论文类型判定、分析深度、待澄清问题 |
| P1 | 通读建骨 | `analysis/10-outline.md` | 一篇一问的通读，先建逻辑骨架再抠细节 |
| P2 | 证据提取 | `analysis/20-claims.md` | 主张—证据表，逐条锁死原文引文与图号 |
| P3 | 实验解剖 | `analysis/30-experiments.md` | 数据集/基线/指标/公平性/消融/开销全表 |
| P4 | 创新点鉴定 | `analysis/40-innovation.md` | 技术分解 + 三条基线对比 + 分级 + 可证伪表述 |
| P5 | 对抗验证 | `analysis/50-critique.md` | 三个独立审查角色并行挑错，主 Agent 反驳与收敛 |
| P6 | 重构与图示 | `analysis/60-method.md` | 方法结构图（Mermaid）+ 复现关键参数表 |
| P7 | 报告写作 | `reports/<slug>_详细版.md` → `reports/<slug>_简略版.md` | 先写详细版，再从详细版抽简略版 |
| P8 | 出稿与校验 | `reports/*.docx` | 编译 Word 并跑交付前校验，失败就回 P7 改 |

阶段细节、每一步的提示词与判据见 → `reference/workflow.md`（**动手前必读**）；
Word 出稿与校验规则见 → `reference/docx-export.md`；简略版模板见 → `reference/brief-template.md`。

### 并行策略（重要）

P2、P3、P4、P5 是天然独立的，**默认并行下发子代理**，不要串行做：

- P2/P3/P4：各自 `subagent` 一个子代理，prompt 用 `reference/subagent-prompts.md` 的模板。
- P5：用 `workflow` 工具一次扇出三个审查角色（复现者 / 历史学家 / 审稿人），要求结构化 JSON 返回，再在本地合成。
- 单篇小论文（≤8 页、非顶会）可以只用主 Agent 串行跑，不要为省事而省略 P5。
- **主 Agent 只做合成与判断**：子代理返回的是素材，创新点分级必须由主 Agent 在合成后才下结论。

## 3. 交付物：三个版本，都出 Word

每次分析交付**同一篇论文的三个版本**，放在**同一个 `reports/` 目录**里：

| 版本 | 篇幅 | 内容 | 用途 |
|---|---|---|---|
| **详细版** `*_详细版.docx` | 不限（通常 8–20 页） | 完整证据链：问题矩阵、方法重构、创新点逐条论证、实验全表、局限、复现路线，以及**需要向作者确认的问题**。**表格、图、引文块都用在这里** | 自己吃透、开题铺垫、导师细读 |
| **简略版** `*_简略版.docx` | **2–3 页（正文 2000–3400 汉字）** | **整段文字叙述，手打报告风格，不摆表格**（最多 1 张）；**不带标题、不写"一句话结论"、不列"要问作者的问题"** | 组会汇报、周报、快速筛选 |
| **摘录版** `*_摘录版.docx` | **最小（正文 ≤2000 汉字）** | **只有三节**：论文在做什么 / 创新点 / 该论文提供的思路。**不评级、不判断、不建议**（出现评级用语即校验 FAIL）；不带标题、不带表格 | 快速了解一篇论文、跨方向交流、给自己的文献卡片 |

**排印（三版一致，固定）**：中文宋体、正文**小四（12 pt）**；英文与数字 **Times New Roman**；**1.5 倍行距**；
标题黑体加粗。由 `docx_export.py` 自动套用，不要手改生成物。

**简略版是"人写的报告"，不是"摘要的表格版"。** 写法要求：

- **不加标题**（文件名即标题，渲染器也不生成标题行）；**不单列"一句话结论"**——判断写进第一段；
- 五节：论文在做什么 → 创新点（逐条一段）→ 实验做到了什么程度 → 主要问题 → 复现与建议；
- **表格是详细版的工具**：简略版通常 0 张表，只在某个数据关系非表不可时留 1 张；
- 每段以加粗短句点题，数字与条件写在句子里（"在 0.8 V、28 nm 下能耗降低 41%"），不要拆成表格列；
- 不出现证据链标记（`[推断]`/`[论文未给出]`）、公式块、Mermaid 源码、复现参数表、参考文献列表；
- **末尾不加"详见详细版 / 过程档案见某目录"这类指引句**——交出去的就是一份自足的文字报告；
- 全文黑色字体（含标题与加粗），由渲染器保证；
- 每个数字都必须能在详细版里找到（出稿时逐条比对）。

**摘录版的边界（最要紧的一条）**：它**只写论文本身**——做了什么、新在哪、能借什么思路。
不写分级（`A/B/C/D 级`）、不写"值得跟进/不值得"、不写"我的结论/我认为"、不写"局限/风险/复现难度"。
校验器会在摘录版出现这些用语时报 FAIL，这是刻意的：摘录版是文献卡片，不是评价。

**写法顺序**：先写详细版（结论与数字的唯一来源）→ 从详细版抽简略版（带判断）→
再从详细版抽摘录版（去判断）。三版的数字都必须能在详细版里找到。

简略版的结论必须给出可执行的判断：**值不值得跟、从哪一点切入、最大风险是什么**；摘录版则相反，只提供材料。

### 详细版必含章节

1. 摘要卡（一页速览：问题 / 方法 / 最强结果 / 证据等级 / 创新点等级 / 我的结论 / 最该问作者的问题）
2. 问题与动机（含 `问题定义矩阵`）
3. 方法重构（含 Mermaid 结构图 + 关键公式的符号表）
4. 技术分解与创新点（每条创新点附：相对基线的差异 → 为什么这算新 → 证据 → 分级 → 可证伪表述）
5. 实验方法与结果解读（实验设计判定表 + 结果原文数据 + 我的解读）
6. 局限与风险（分"作者承认的"与"我发现的"两类）
7. 与相关工作的关系（可含多篇对比矩阵）
8. 对我的研究：可复现路线 / 可切入的创新机会 / 待澄清问题
9. 参考文献与引用信息

模板 → `reference/report-template.md`（详细版）、`reference/brief-template.md`（简略版）、
`reference/notes-template.md`（摘录版：只写论文本身，不评级）。

### 创新点的分级口径（必须显式标注）

| 等级 | 定义 | 判据 |
|---|---|---|
| **A 级 新范式** | 换了问题框架或引入新计算原语，后续工作会跟 | 不能用已有方法的参数化/组合来解释 |
| **B 级 新方法** | 在既有框架内提出新的结构/机制/训练策略，贡献是可测量的 | 有对应消融实验支撑，去掉它就退化 |
| **C 级 新组合/新应用** | 已知模块的新组合或迁移到新任务/新工艺节点 | 各模块单独已知，组合的有效性有待论证 |
| **D 级 增量** | 工程微调、超参/规模效应、更强的基线实现 | 差异可被算力或调参解释 |

分级的三条基线（评估创新性时逐条对照，口径见 `reference/novelty-rubric.md`）：
**① 本文自报的最近邻工作 → ② 同期同类工作 → ③ 该领域公认的技术母题（经典方法）**。

## 4. 产物目录约定（每篇文献一个独立文件夹）

**每篇文献一个独立文件夹**，文件夹里自带它的交付物、过程档案与素材；`PaperAnalysis/` 只作为总目录，
本身不放任何单篇的文件：

```
<工作区>/PaperAnalysis/
├── <YYYY-MM-DD>_<论文短标题甲>/        ← 甲论文的全部内容（自包含，可整体拷走）
│   ├── reports/                        ← 唯一交付目录：三版 Word + 同源 markdown
│   │   ├── <slug>_详细版.md / .docx
│   │   ├── <slug>_简略版.md / .docx
│   │   └── <slug>_摘录版.md / .docx
│   ├── analysis/                       ← 过程档案（供下一篇复用）
│   │   ├── 00-context.md … 60-method.md
│   │   ├── check.json                  ← 出稿校验明细
│   │   └── source/paper.txt            ← 从 PDF 抽取的正文（引文核对基准）
│   ├── assets/                         ← 该论文的图表截图（docx 内嵌用）
│   └── sources.md                      ← 该论文的引用信息与检索链接
└── <YYYY-MM-DD>_<论文短标题乙>/        ← 乙论文，同上
```

文件夹命名：`<YYYY-MM-DD>_<英文小写连字符短标题>`。**一篇论文一个文件夹，互不混放**：
需要交付或交接某篇时，直接整包拷该文件夹即可，`reports/` 是给别人的，`analysis/` 是自己的。

多篇对比：`<工作区>/PaperAnalysis/<YYYY-MM-DD>_对比_<主题>/`，交付物同样是
`reports/comparison_详细版.docx`、`reports/comparison_简略版.docx` 与 `reports/comparison_摘录版.docx`
（矩阵模板见 `reference/compare-template.md`）。对比也是独立文件夹，不与被对比的单篇混放。

**命名硬约束**：日期用 `YYYY-MM-DD`；短标题用英文小写连字符（如 `configurable-adder-tree`），
避免中文与空格（防止命令行与工具链路径问题）；两个版本的文件名只差"详细版/简略版"四个字。

**中间件绝不写进 `reports/`**：该目录只放六份报告文件（三版 md + 三版 docx）。
过程档案、校验明细、抽取的正文都留在 `analysis/`。这样交付时把 `reports/` 整个拷给导师，
不会夹带内部推断痕迹与未完成标记。

## 5. 学科适配（集成电路工程）

本技能默认按**集成电路/微电子/EDA/电路与系统**方向的口径解读，术语与指标定义见 `reference/ic-domain-notes.md`：

- 指标必须带条件：功耗（动态/静态/总功耗 @Vdd/工艺角/温度/频率）、时序（WNS/TNS/关键路径延迟）、面积（μm²/mm²/等效门数）、能效（TOPS/W、pJ/op）、精度（是否含量化损失、是否 post-layout）。
- 工艺与流程必须分清：仿真 / RTL / 综合 / 布局布线（post-layout）/ 流片测试。**把仿真数据当作流片结论是致命误读**，报告里必须显式区分。
- 电路类论文重点看：工艺节点、电源电压、架构（模拟/数字/混合）、PVT 覆盖、失配与噪声处理、测试芯片面积与实测条件。
- EDA/算法类论文重点看：基准测试集与版本、对照工具与版本、运行时是否含编译/综合时间、是否能扩展到更大规模（scalability）。

若论文属于其他方向（器件、封装、光电子、通信电路），仍按同一流水线执行，但需在 `00-context.md` 里声明"本次按 X 方向口径解读"，并在指标表旁注明该方向惯例。

## 6. 交付前的自检（不可跳过）

分两步：**自动校验** + **人工清单**。

1. **自动校验**：P8 调 `paper_docx`（本 preset 自带工具）编译 Word 并跑 `docx_check`，
   它会检查：残留未解决标记、简略版与摘录版的必备章节与篇幅、**摘录版是否混入评级/判断用语**、三版数字一致性、
   英文引文能否在 `analysis/source/paper.txt` 中逐字找到、图片引用是否存在。
   **校验 FAIL 必须回去改，不允许带着 FAIL 交付。** 规则细节见 `reference/docx-export.md`。
2. **人工清单**：逐条过一遍 → `reference/checklist.md`。

特别地：

- 报告里出现的每个数字，都能在 `20-claims.md` / `30-experiments.md` 里找到出处。
- 只有一处引用来源的"结论"要标注为**单点证据**，不能升格为事实。
- 详细版摘要卡里的"我的结论"必须与正文第 4、6 章不矛盾；简略版的结论必须与详细版一致。
- 明确写出**论文没有回答的问题**——审稿人和导师最先问的正是这些。
- 简略版不可以出现 `[推断]` 之类的证据链标记（那是详细版的留痕，不是给导师看的内容）。

## 7. 风格与语气

- 中文正文，专业术语保留英文原词（如 adder tree、post-layout、ablation）。
- 判断要敢下但要有据：写"从消融看该模块贡献约 x%，但缺少与 y 的对照，因此 B 级成立的证据尚不充分"，不写"该工作创新性一般"。
- 禁止空话（"具有重要意义""效果显著"）；每个形容词后面要么跟数字，要么跟引文。
- 给读者的时间分层的：摘要卡 2 分钟能读完，全文 20 分钟能读完。
